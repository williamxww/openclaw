# WPS 协作接入 OpenClaw

目标：在 WPS 协作里创建一个机器人入口，把用户消息转发到本机 WSL 内的 OpenClaw Gateway，再把 OpenClaw 的回复发回 WPS 协作。

结论先放前面：

- 如果要做“群里 @ 机器人 -> OpenClaw 回复”的交互，优先用 **webhook 机器人**。官方文档明确支持 webhook 机器人配置回调地址，并在群内 @ 机器人时把消息 POST 到第三方服务。
- 如果要做“企业应用向用户/会话推送 OpenClaw 结果”，用 **企业自建应用 + 应用机器人能力**。官方应用机器人文档主要覆盖创建应用、设置可见范围、开放接口发消息和消息审核。
- OpenClaw 在本机 WSL 内，不应该直接暴露给 WPS 公网回调。推荐加一个 **公网 HTTPS 桥接服务**：WPS 只访问桥接服务；桥接服务再访问 WSL 的 `http://127.0.0.1:18789` 或 `http://<WSL-IP>:18789`。

## 1. 官方能力边界

### 1.1 应用机器人

WPS 开放平台的“应用机器人”是 WPS 协作里的消息通知渠道。企业内部系统可以通过应用机器人集成到 WPS 协作，做重要消息或任务推送。

创建路径：

1. 进入 WPS 开放平台开发者后台。
2. 点击“创建应用”，选择“企业自建应用”。
3. 填写应用名称、应用描述、上传应用图标，创建应用。
4. 在应用能力里开启 WPS 协作机器人能力。
5. 在“应用发布-版本管理”的版本详情里配置“可用范围”。应用机器人只能给可见范围内的用户发送消息。
6. 申请消息权限：`kso.chat_message.readwrite`。

应用机器人发送消息有两种方式：

- 在开发者后台用可视化界面发送。
- 调用开放接口发送或批量发送。

单条消息接口：

```text
POST https://openapi.wps.cn/v7/messages/create
```

关键要求：

- Header 需要 `Content-Type: application/json`。
- Header 需要 `Authorization: Bearer {access_token}`。
- 如果后台开启了接口签名，还需要 `X-Kso-Date` 和 `X-Kso-Authorization`。
- 权限要求是 `kso.chat_message.readwrite`。
- 接收者必须在应用可用范围内。
- 应用机器人消息最多 5000 个字符。
- 支持发送给指定用户、指定会话、指定关联组织成员。
- 给群组发送时，机器人需要在该群组中。

最小文本消息体形态：

```json
{
  "type": "text",
  "receiver": {
    "receiver_id": "<user_id_or_chat_id>",
    "type": "user"
  },
  "content": {
    "text": {
      "content": "OpenClaw 回复内容",
      "type": "markdown"
    }
  }
}
```

如果 `receiver.type` 是群会话，用：

```json
{
  "receiver": {
    "receiver_id": "<chat_id>",
    "type": "chat"
  }
}
```

批量消息接口：

```text
POST https://openapi.wps.cn/v7/messages/batch_create
```

它适合批量通知，不适合即时对话。官方说明该接口是异步接口，会有一定延迟；单用户或群聊、对即时性要求高的场景应使用单条发送消息接口。

### 1.2 webhook 机器人

webhook 机器人是在 WPS 协作群聊里添加的群机器人。它有两个重要能力：

- 调用机器人 webhook 地址向群里发送消息。
- 配置回调地址后，在用户群内 @ 机器人时，把消息 POST 到第三方服务。

创建路径：

1. 在群聊里点击右上角“...”。
2. 进入“群机器人”。
3. 添加 webhook 机器人。
4. 填写机器人名称和简介。
5. 保存 webhook 地址，格式类似：

```text
https://xz.wps.cn/api/v1/webhook/send?key=xxxxxxx
```

回调配置：

1. 在 webhook 机器人设置里填写回调 URL，例如：

```text
https://openclaw-bridge.example.com/wps/webhook
```

2. WPS 会先对这个地址发起 GET 校验。
3. 桥接服务需要返回：

```json
{
  "result": "ok"
}
```

4. 当用户在群里 @ 机器人时，WPS 会 POST 消息到该地址。官方示例字段包括：

```json
{
  "chatid": 12345,
  "creator": 2324234,
  "content": "@webhook机器人 111",
  "reply": {
    "reply_content": "回复内容",
    "reply_creator": 1234
  },
  "robot_key": "xxx",
  "url": "https://xxxx",
  "ctime": 3452452
}
```

5. 桥接服务收到 POST 后应快速返回：

```json
{
  "result": "ok"
}
```

然后后台异步调用 OpenClaw，并把结果通过 webhook 发送地址发回群聊。

## 2. 推荐架构

```text
WPS 协作
  |
  | HTTPS 回调 / 发送消息 API
  v
公网桥接服务
  |
  | HTTP，内网或本机转发
  v
OpenClaw Gateway in WSL
  |
  | Agent turn
  v
OpenClaw agent / tools / workspace
```

桥接服务职责：

- 暴露公网 HTTPS URL 给 WPS。
- 处理 webhook 机器人 GET 校验或应用事件订阅 challenge。
- 验证 WPS 请求签名或 webhook 安全设置。
- 清洗用户输入，例如去掉 `@机器人` 前缀。
- 调 OpenClaw Gateway。
- 把 OpenClaw 回复发送回 WPS。
- 保存 `chatid`、`creator`、`message_id`、OpenClaw session key 的映射，保证同一个群或同一个用户可以延续会话。

不要让 WPS 直接访问 OpenClaw Gateway：

- OpenClaw Gateway 默认是本机服务，常用端口是 `18789`。
- dev profile 常用端口是 `19001`。
- Gateway 需要 `Authorization: Bearer <gateway-token>`。
- 直接公网暴露 Gateway 会把本机 agent、工具和工作区暴露给外部网络，风险太高。

## 3. OpenClaw 侧准备

在 WSL 里确认 Gateway 已启动：

```bash
openclaw gateway status
```

默认 profile：

```text
http://127.0.0.1:18789
```

dev profile：

```text
http://127.0.0.1:19001
```

读取 token：

```bash
jq -r .gateway.auth.token ~/.openclaw/openclaw.json
```

dev profile：

```bash
jq -r .gateway.auth.token ~/.openclaw-dev/openclaw.json
```

如果 dev profile 没有固定 token，先设置：

```bash
node openclaw.mjs --dev config set gateway.auth.mode token
node openclaw.mjs --dev config set gateway.auth.token <随机强口令>
```

桥接服务调用 OpenClaw 的推荐接口是 OpenAI 兼容 HTTP 网关：

```text
POST /v1/chat/completions
```

如果该端点没有启用，需要在 OpenClaw 配置里打开：

```json
{
  "gateway": {
    "http": {
      "endpoints": {
        "chatCompletions": {
          "enabled": true
        }
      }
    }
  }
}
```

示例：

```bash
curl -sS http://127.0.0.1:18789/v1/chat/completions \
  -H "Authorization: Bearer $OPENCLAW_GATEWAY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "<已配置的模型ID，例如 qwen3.5>",
    "messages": [
      { "role": "user", "content": "你好，帮我总结一下今天的任务" }
    ],
    "stream": false
  }'
```

如果桥接服务跑在 Windows，而 OpenClaw 跑在 WSL：

- Windows 访问 WSL 里监听 `127.0.0.1` 的服务，通常可直接用 `http://127.0.0.1:18789`，取决于 WSL 端口转发状态。
- 如果访问不通，在 WSL 里查 IP：

```bash
hostname -I
```

然后 Windows 侧访问：

```text
http://<WSL-IP>:18789
```

如果桥接服务跑在云主机，不要直接打本机 WSL IP。使用下面任一方案：

- Tailscale / ZeroTier，把云主机和本机 WSL 加入同一个私网。
- SSH 反向隧道，让云主机本地端口转发到 WSL 的 `18789`。
- Cloudflare Tunnel / frp / ngrok，但只暴露桥接服务，不暴露 OpenClaw Gateway。

## 4. webhook 机器人接入流程

这是最适合“在群里问 OpenClaw”的方案。

### 4.1 创建机器人

1. 在目标 WPS 协作群聊中添加 webhook 机器人。
2. 保存发送消息 webhook 地址。
3. 配置回调地址：

```text
https://openclaw-bridge.example.com/wps/webhook
```

### 4.2 桥接服务处理逻辑

GET 校验：

```ts
app.get("/wps/webhook", (_req, res) => {
  res.json({ result: "ok" });
});
```

POST 回调：

```ts
app.post("/wps/webhook", async (req, res) => {
  res.json({ result: "ok" });

  const { chatid, creator, content } = req.body;
  const prompt = stripBotMention(content);
  const sessionKey = `wps:webhook:${chatid}:${creator}`;

  const answer = await callOpenClaw({
    sessionKey,
    prompt
  });

  await sendWpsWebhookMarkdown({
    webhookUrl: process.env.WPS_WEBHOOK_URL!,
    text: answer
  });
});
```

发送回群聊：

```ts
async function sendWpsWebhookMarkdown(params: {
  webhookUrl: string;
  text: string;
}) {
  await fetch(params.webhookUrl, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      msgtype: "markdown",
      markdown: {
        text: params.text.slice(0, 5000)
      }
    })
  });
}
```

调用 OpenClaw：

```ts
async function callOpenClaw(params: {
  sessionKey: string;
  prompt: string;
}) {
  const response = await fetch(`${process.env.OPENCLAW_BASE_URL}/v1/chat/completions`, {
    method: "POST",
    headers: {
      "Authorization": `Bearer ${process.env.OPENCLAW_GATEWAY_TOKEN}`,
      "Content-Type": "application/json"
    },
    body: JSON.stringify({
      model: process.env.OPENCLAW_MODEL,
      messages: [
        {
          role: "system",
          content: `你正在 WPS 协作群聊中回复用户。保持简洁，必要时用 Markdown。session=${params.sessionKey}`
        },
        {
          role: "user",
          content: params.prompt
        }
      ],
      stream: false
    })
  });

  if (!response.ok) {
    throw new Error(`OpenClaw HTTP ${response.status}: ${await response.text()}`);
  }

  const json = await response.json() as {
    choices?: Array<{ message?: { content?: string } }>;
  };
  return json.choices?.[0]?.message?.content?.trim() || "OpenClaw 没有返回可展示内容。";
}
```

### 4.3 安全设置

webhook 机器人至少开启一种安全设置：

- 自定义关键词。
- IP 白名单。
- 签名校验。
- 特权用户设置。

生产环境建议同时做：

- 桥接服务只接受 WPS 回调路径。
- 校验 `robot_key` 是否匹配预期机器人。
- 对 `chatid` 做 allowlist。
- 对 `creator` 做 allowlist 或权限映射。
- 对 OpenClaw 调用设置超时，例如 60 秒。
- OpenClaw 长回复截断到 5000 字符，超过时分段发送或保存为文档链接。

## 5. 应用机器人接入流程

这是适合“企业应用通知用户/会话”的方案。如果你的目标是让 OpenClaw 把分析结果、任务进度、审批提醒推送到 WPS 协作，用这个。

### 5.1 创建企业自建应用

1. 进入 WPS 开放平台开发者后台。
2. 点击“创建应用”。
3. 选择“企业自建应用”。
4. 填应用名称，例如 `OpenClaw Assistant`。
5. 填应用描述，例如“企业内部 OpenClaw 助手，用于任务处理、知识问答和工作流通知”。
6. 上传图标并创建。

### 5.2 开启机器人能力和权限

1. 进入应用详情。
2. 打开应用能力，选择 WPS 协作机器人。
3. 在权限范围里申请：

```text
kso.chat_message.readwrite
```

4. 在应用发布/版本管理里配置可用范围。
5. 发布或提交企业管理员审核。

### 5.3 配置事件回调

如果需要从 WPS 事件驱动 OpenClaw：

1. 在“开发者后台-事件与回调”配置接收事件 URL。
2. 在“开发者后台-事件回调”选择需要订阅的事件。
3. 申请并开通事件所需权限。
4. WPS 会对事件地址发 POST challenge。

challenge 请求示例：

```json
{
  "challenge": "string"
}
```

桥接服务需要在 1 秒内原样返回：

```json
{
  "challenge": "string"
}
```

事件推送要求：

- WPS 会 POST `application/json` 到事件 URL。
- 应用收到后需要在 3 秒内返回 HTTP 200。
- 失败后 WPS 以 1 秒、2 秒间隔重试，最多重试 2 次。
- 事件消息体是加密的，需要先验签再解密。

事件加密体字段：

```json
{
  "topic": "string",
  "operation": "string",
  "time": 1704074400,
  "nonce": "string",
  "signature": "string",
  "encrypted_data": "string"
}
```

验签原文：

```text
access_key:topic:nonce:time:encrypted_data
```

其中 `access_key` 是应用 APPID；签名用应用 APPKEY 做 HMAC-SHA256，再做 URL 安全、无填充的 base64 编码。解密使用 AES-CBC，密钥是 APPKEY 的 MD5，`nonce` 作为 IV。

注意：是否能收到“用户发给应用机器人”的消息，要以应用后台可选事件列表为准。当前已确认的官方应用机器人主文档强调的是推送消息；明确支持群内 @ 回调的是 webhook 机器人。

### 5.4 应用机器人发送 OpenClaw 回复

桥接服务调用 WPS 单条消息接口：

```ts
async function sendWpsAppMessage(params: {
  accessToken: string;
  receiverId: string;
  receiverType: "user" | "chat" | "enterprise_partner_user";
  text: string;
}) {
  const body = JSON.stringify({
    type: "text",
    receiver: {
      receiver_id: params.receiverId,
      type: params.receiverType
    },
    content: {
      text: {
        content: params.text.slice(0, 5000),
        type: "markdown"
      }
    }
  });

  const headers: Record<string, string> = {
    "Authorization": `Bearer ${params.accessToken}`,
    "Content-Type": "application/json"
  };

  // 如果开发者后台开启了 KSO-1 接口签名，在这里补充：
  // headers["X-Kso-Date"] = new Date().toUTCString();
  // headers["X-Kso-Authorization"] = buildKso1Signature(...);

  const response = await fetch("https://openapi.wps.cn/v7/messages/create", {
    method: "POST",
    headers,
    body
  });

  if (!response.ok) {
    throw new Error(`WPS message HTTP ${response.status}: ${await response.text()}`);
  }
}
```

KSO-1 签名规则：

```text
X-Kso-Authorization = "KSO-1 " + APPID + ":" + signature
signature = HMAC-SHA256(
  secretKey = APPKEY,
  message = "KSO-1" + Method + RequestURI + ContentType + KsoDate + sha256(RequestBody)
)
```

例如发送消息接口的 `RequestURI` 是：

```text
/v7/messages/create
```

## 6. 本机开发调试方案

开发阶段可以这样跑：

```text
WPS -> ngrok / Cloudflare Tunnel / frp -> 本机桥接服务 -> WSL OpenClaw
```

桥接服务环境变量：

```bash
OPENCLAW_BASE_URL=http://127.0.0.1:18789
OPENCLAW_GATEWAY_TOKEN=<openclaw gateway token>
OPENCLAW_MODEL=<已配置的模型ID，例如 qwen3.5>

WPS_WEBHOOK_URL=https://xz.wps.cn/api/v1/webhook/send?key=xxxxxxx
WPS_APP_ID=<APPID>
WPS_APP_KEY=<APPKEY>
```

如果桥接服务在 Windows 上访问 WSL 不通，换成：

```bash
OPENCLAW_BASE_URL=http://<WSL-IP>:18789
```

公网回调 URL 必须是 HTTPS；如果使用 ngrok、Cloudflare Tunnel 或 frp，只把桥接服务端口暴露出去，不要暴露 OpenClaw Gateway 端口。

## 7. 建议的落地顺序

1. 先用 webhook 机器人打通群内 @ 回调。
2. 桥接服务收到 GET 时返回 `{ "result": "ok" }`。
3. 桥接服务收到 POST 时先立即返回 `{ "result": "ok" }`。
4. 后台异步调用 OpenClaw `/v1/chat/completions`。
5. 用 webhook 发送地址把 OpenClaw 回复发回群。
6. 验证稳定后，再创建企业自建应用机器人，用应用机器人接口做正式企业通知。
7. 如果开放平台后台提供了可用的“消息类事件”，再把应用事件订阅接入同一个桥接服务。

## 8. 检查清单

- WPS webhook 机器人回调 GET 校验通过。
- WPS @ 机器人后，桥接服务收到 POST。
- 桥接服务不会同步等待 OpenClaw，能快速 ACK。
- OpenClaw Gateway 在 WSL 内可访问。
- `OPENCLAW_GATEWAY_TOKEN` 和 WPS webhook key / APPKEY 没有写进代码仓库。
- 长回复有 5000 字符截断或分段策略。
- 群 ID 和用户 ID 有权限控制。
- 生产回调 URL 使用 HTTPS。
- 应用机器人发送消息时，接收者在应用可用范围内。
- 如果开启 KSO-1，签名使用发送时的原始 JSON 字节计算，不能签名后再改 JSON 格式。
